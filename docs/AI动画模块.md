# AI 动画 · 真正的骨骼动画短片

> 不是「一张静态图 + 平移缩放」，也不是「几张图拼起来 + 转场」。
> 角色被拆成 **9 个可以独立运动的部件**，按**动作时间轴**逐帧演出。

---

## 一、为什么之前是「PPT 感」，现在不是

| | 伪动画（Ken Burns） | 本模块（骨骼动画） |
| --- | --- | --- |
| 画面来源 | 一张静态图 | 9 个独立部件实时合成 |
| 角色在动吗 | 整块平移缩放，人是僵的 | 手臂前后摆、腿交替迈、头微点、身体上下起伏 |
| 有没有弹性 | 没有 | 挤压拉伸（起跳前蹲、腾空拉长、落地压缩） |
| 有没有预备与跟随 | 没有 | 跳之前先蹲一下；身体停下后呆毛还在晃 |
| 表情变吗 | 不变 | 按动作切表情（跑=惊奇、跳=星星眼、摔倒=难过） |
| 场景动吗 | 只有镜头在动 | 微尘上浮、叶子摆动、光斑流动、速度线掠过 |
| 帧率 | 取决于图片 | 浏览器原生 60fps |

## 二、动作时间轴（迪士尼十二法则的最小可用子集）

以「跳」为例，一条时间轴长这样：

```
0%    身体位于 0px，   无挤压                          ← 站立
18%   身体下移 30px，  挤压 scale(1.16, 0.84)          ← 预备动作（蹲下蓄力）
42%   身体上移 110px， 拉伸 scale(0.86, 1.14)          ← 发力腾空
58%   身体上移 124px， 轻微拉伸                         ← 顶点短暂悬停
80%   身体下移 22px，  挤压 scale(1.14, 0.86)           ← 落地缓冲
100%  回到 0px                                        ← 回弹站定
```

**11 个动作**：呼吸 / 走 / 跑 / 跳 / 伸手 / 抱头 / 转圈 / 摔倒 / 踮脚 / 趴下 / 后退。

**关节轴心**用 `transform-box: fill-box` + `transform-origin` 设在真正的关节上：

| 部件 | 轴心 | 效果 |
| --- | --- | --- |
| 左臂 / 右臂 | 肩（顶部内侧） | 摆臂是绕肩膀转，不是整条平移 |
| 左腿 / 右腿 | 胯（顶部） | 迈步是绕胯转 |
| 身体 | 脚底中心 | 蹲下时从脚底压，不是从腰压 |
| 头 | 脖子（底部中心） | 点头是绕脖子 |
| 呆毛 / 尾巴 | 根部 | 跟随动作，身体停了它还在晃 |

## 三、动作从剧情推出来（不是随机播）

页面数据里的 `pose` 是**静态姿态**（stand / lie / reach），
动画需要的是**动作**（走 / 跑 / 跳 / 摔 / 转圈 / 抱头）。两者之间做了一层语义推导：

1. **台词关键词优先**：台词里写了「跑」就真的跑起来，写了「跳」就跳
2. **否则按故事节拍**：好奇→踮脚、遇到问题→后退、情绪低谷→抱头、小挫折→摔倒、成功→转圈

实测 8 本全部分镜后的动作分布：

```
tiptoe 11   jump 9   walk 3   back 10   reach 13   spin 7   lie 9   run 4
```

## 五、接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/animation` | 骨骼动画播放器 |
| GET | `/api/anim/storyboard?id=&grade=` | 动画分镜：每镜的画面 SVG、动作时间轴、场景动态、关键帧 CSS |

```jsonc
// GET /api/anim/storyboard?id=wake&grade=2
{
  "ok": true, "title": "小AI 醒来了",
  "shots": [{
    "index": 1, "camera": "特写",
    "action": "tiptoe", "actionLabel": "踮起脚尖，偷偷往前看",
    "duration": 1.8, "loop": true, "expr": "wonder",
    "ambient": [{ "key": "dust", "name": "漂浮的微尘" }, { "key": "leaf", "name": "叶子轻轻摆动" }],
    "timeline": [ { "at": 0, "body": -6, "legL": -10, "legR": -10 }, … ],
    "art": "<svg>…含 k0-body / k0-armL / k0-legR 等骨骼分组…</svg>",
    "say": { "who": "ai", "text": "唔……天亮了吗？" },
    "arcName": "日常状态", "logicTrigger": "因为盒子里传出声音，所以点点决定凑过去看一看"
  }],
  "css": "@keyframes k0-body { … } @keyframes k0-armL { … } …"
}
```

**注意**：同一个页面上会同时存在多个角色的骨骼动画，所以每个镜头的 class 都带自己的前缀
（`k0-`、`k1-`…）。否则同一个 `.pbA-body` 被多条 `@keyframes` 抢，画面会错位。

## 六、两个必须注意的坑

| 坑 | 现象 | 原因与修法 |
| --- | --- | --- |
| 两条动画抢同一个属性 | 挤压生效了但位移没了（或反过来） | 同一个元素上两条动画都写 `transform`，**后一条整体覆盖前一条**。位移与挤压必须在同一条 `transform` 里一次写全 |
| 多实例 class 撞车 | 同页四个角色全部错位、头身分离 | 所有实例共用 `.pbA-body`，最后一条 `@keyframes` 赢。必须按实例加前缀 |

## 七、技术路径说明

提示词里提到的三条真动画路径：

| 路径 | 本机可行性 | 本项目选择 |
| --- | --- | --- |
| AI 视频大模型（Sora / Runway / 可灵） | 需联网、需付费、结果不可控 | ✗ 机房可能直接不可用 |
| WebGL / Three.js 3D 骨骼 | 可行，但要引入 three.js（外部依赖） | ✗ 与「零依赖、断网可用」冲突 |
| **2D 骨骼 + CSS 关键帧**（Lottie/Spine 的同类思路） | **纯矢量、无依赖、浏览器原生 60fps** | ✅ **本项目采用** |

这与提示词里「最低保底方案」的建议一致：**分层视差 + 角色骨骼动画 + 镜头推拉**，
比低质量的 AI 视频更稳定，也一样能实现视频内互动。
区别在于本项目没有引入 Lottie，而是**直接用 SVG 分组 + CSS 关键帧**——
产物是可读的矢量代码，任何一个浏览器都能播，断网也不受影响。

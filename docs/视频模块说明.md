# AI 视频 / AI 动画 · 逻辑与代码说明

> 这一块实际上有**两条并行的技术路线**，页面上都能进：
>
> | | AI 视频 | AI 动画 |
> | --- | --- | --- |
> | 入口 | `/video` | `/animation` |
> | 产物 | 一个 **MP4 文件**，可下载 | **浏览器里实时播的骨骼动画** |
> | 技术 | 帧渲染 → Chrome 截图 → ffmpeg 编码 | SVG 分组 + CSS 关键帧 |
> | 角色会动吗 | 按页停留，靠镜头与字幕 | **关节独立运动、口型、真实位移** |
> | 用途 | 老师带走、投屏、发家长 | 课堂现场演、视频内互动 |

## 一、AI 视频（MP4 路线）

### 1.1 数据流

```
POST /api/video/render  { id, grade, voice, subtitle, pages }
        │
        ▼
pb-video-jobs.create()  →  入队，立刻返回 202 + jobId
        │
        ▼  （后台 setImmediate，一次只跑一个）
pb-video.render(book, opt, onStep)
        │
        ├─ ① 逐页生成帧 HTML          frameHtml(page)
        │     1024×640 的绘本 SVG 居中 + 底部渐变字幕条（拼音 + 角色名 + 正文）
        │
        ├─ ② 无头 Chrome 截图          shoot() → PNG
        │
        ├─ ③ 语音合成                  speak() → WAV（Windows System.Speech，中文女声）
        │     用 wavSeconds() 读 WAV 头算时长 → 决定这一页停留多久
        │
        ├─ ④ ffmpeg 合成
        │     concat(duration) → libx264 → 抽帧做封面 → 混入 AAC 音轨
        │
        ▼
{ ok, file, poster, seconds, bytes, pages, withAudio }
        │
        ▼
GET /media/videos/<jobId>/video.mp4   （serveFrom 支持 Range，可拖进度条）
```

### 1.2 依赖探测（缺什么如实说）

```js
function findFfmpeg()      // FFMPEG_PATH → 常见安装路径 → PATH
function findChrome()      // CHROME_PATH  → Program Files 下的 chrome.exe
function findPowershell()  // POWERSHELL_PATH → Windows 自带的 powershell.exe

function available() {
  return { ok, ffmpeg, chrome, tts, reason };
}
```

**没有 package.json，没有任何 npm 依赖。** 全部能力来自操作系统自带组件。

### 1.3 异步执行器（这一段是必须的）

```js
/** 异步执行：渲染要跑几十秒，绝不能阻塞服务器的事件循环 */
function run(cmd, args, opt) {
  return new Promise(function (resolve, reject) {
    const child = execFile(cmd, args, { timeout, maxBuffer, windowsHide: true },
      function (err, stdout, stderr) {
        if (err) { err.stderr = stderr; reject(err); } else resolve({ stdout, stderr });
      });
    if (opt.input && child.stdin) child.stdin.end(opt.input);
  });
}
```

最初用的是 `execFileSync`，结果渲染期间整个服务卡死——
这也是「改了代码没生效」之外最容易误判为 bug 的地方：**服务器其实只是被自己阻塞了。**

### 1.4 帧清单（踩过的坑都在这里）

```js
/* 画面：用 concat 的 duration 指令给每张图定时长。
   不能把同一张图重复列 90 次 —— 那会让 PTS 溢出、只出一帧。 */
pngs.forEach((png, i) => {
  lines.push("file '" + png.replace(/\\/g, '/') + "'");
  lines.push('duration ' + (segments[i].dur || HOLD).toFixed(3));
});
/* 最后一张要再列一次，concat 才会把上一段的时长算进去 */
lines.push("file '" + pngs[pngs.length - 1].replace(/\\/g, '/') + "'");
```

| 坑 | 现象 | 原因 |
| --- | --- | --- |
| 重复列同一张图 | 视频只有 **0.04 秒**、一帧 | concat 把连续重复图片当成同一帧，PTS 溢出 |
| 清单带 BOM | `unknown keyword '﻿file'` | PowerShell `Set-Content -Encoding utf8` 会写 BOM，改用 Node 写 |
| 不给总时长 | 出片时长不对 | 显式传 `-t totalSec` |
| 音轨对不齐 | 配音与画面对不上 | 每段先 `apad` 补到与画面等长，再 `concat` |

### 1.5 任务队列

```js
let runningId = null;
function pump() {
  if (runningId) return;                       // 一次只跑一个
  const next = [...jobs.values()].filter(j => j.status === 'queued')[0];
  if (!next) return;
  runningId = next.id;
  setImmediate(async () => {                   // 先让 HTTP 响应发出去
    try {
      const r = await video.render(next.book, { dir: next.dir, ... },
        (t, p) => { next.step = t; next.percent = p; });   // 进度回调
      next.status = r.ok ? 'done' : 'failed';
      ...
    } finally { runningId = null; pump(); }
  });
}
```

进度通过 `GET /api/video/job?id=` 轮询，前端每 900ms 问一次。

## 二、AI 动画（骨骼动画路线）

### 2.1 三段式结构

```
pb-timeline.js   动作时间轴：11 个动作的关键帧数据（纯数据，不含渲染）
       │
       ▼
pb-anim.js       把时间轴翻译成 CSS @keyframes + 组装 SVG
       │
       ▼
picturebook.js   播放器：逐镜播放、口型同步、互动暂停
```

### 2.2 角色骨骼绑定（pb-cast.js 的 rigOf）

```
x-halo      光晕（留在地上，不跟角色走）
x-shadow    投影（跟着角色走，随远近微微缩放）
x-body      ← 水平位移 + 垂直位移 + 挤压拉伸
  ├─ x-legL / x-legR      绕「胯」旋转
  ├─ x-armL / x-armR      绕「肩」旋转
  ├─ x-hair               跟随动作：身体停了它还在晃
  └─ x-head               绕「脖子」点头
       ├─ x-eyes           眨眼
       ├─ x-mouth          口型同步
       └─ x-extra          汗滴 / 问号 / 星星
```

**层级是关键**：水平位移施加在 `x-body` 上，头、手臂、腿必须是它的**子节点**。
之前它们是兄弟节点，于是出现「身体往前走了、头还留在原地」。

轴心用 `transform-box: fill-box` + `transform-origin` 设在真正的关节上：

```js
const ORIGIN = {
  'pbA-armL': '76% 22%',   // 肩（顶部内侧）
  'pbA-armR': '24% 22%',
  'pbA-legL': '50% 12%',   // 胯
  'pbA-legR': '50% 12%',
  'pbA-body': '50% 96%',   // 脚底中心：蹲下时从脚底压
  'pbA-head': '50% 92%',   // 脖子
  'pbA-hair': '50% 100%'   // 呆毛根部
};
```

### 2.3 动作时间轴（pb-timeline.js）

以「跳」为例，遵守迪士尼十二法则里的预备动作、挤压拉伸、跟随回弹：

```js
jump: {
  label: '先蹲一下，再蹦起来', dur: 1.5, loop: false,
  frames: [
    { at: 0,    body: 0,    legL: 0,   legR: 0,   squash: 0 },                    // 站立
    { at: 0.18, body: 30,   legL: 14,  legR: 14,  squash: 0.16, ease: 'anticipate' }, // 预备：蹲下蓄力
    { at: 0.42, body: -110, legL: -14, legR: -14, armL: -150, armR: 150, squash: -0.14, ease: 'settle' }, // 发力腾空
    { at: 0.58, body: -124, legL: -8,  legR: -8,  armL: -158, armR: 158, squash: -0.06 }, // 顶点悬停
    { at: 0.8,  body: 22,   legL: 12,  legR: 12,  squash: 0.14, ease: 'settle' }, // 落地缓冲
    { at: 1,    body: 0,    legL: 0,   legR: 0,   squash: 0 }
  ]
}
```

**走路带真实位移**（这一段是「PPT 感」和「动画片」的分界线）：

```js
walk: {
  dur: 5.4, loop: true,
  frames: [
    { at: 0,    dx: -52,  armL: -26, armR: 26,  legL: 22,  legR: -22, op: 0.2 },  // 从左侧淡入
    { at: 0.13, dx: 34,   armL: 20,  armR: -20, legL: -18, legR: 18 },
    { at: 0.26, dx: 142,  ... },
    { at: 0.4,  dx: 236,  ... },                       // 走到右侧
    { at: 0.6,  dx: 236,  body: -3 },                  // 站定喘气：位移停住
    { at: 0.92, dx: 236,  op: 0 },                     // 淡出
    { at: 1,    dx: -52,  op: 0 }                      // 不可见时归位，掩盖循环跳变
  ]
}
```

**为什么要 5.4 秒**：如果整段时间轴都在走路，循环回起点会「瞬间闪回」。
所以设计成 **前 40% 走路、后 60% 站定并淡出**。

### 2.4 时间轴 → CSS 关键帧（pb-anim.js）

```js
/**
 * 注意：同一个元素上如果有两条动画都写 transform，后一条会整体覆盖前一条，
 * 所以「位移 + 挤压拉伸」必须在同一个 transform 里一次写全，不能拆成两条动画。
 */
function keyframes(name, frames, build) {
  const steps = frames.map(f => {
    const at = Math.round(f.at * 1000) / 10;
    const e = f.ease ? EASE_CSS[f.ease] : null;
    return '  ' + at + '% { transform: ' + build(f) + (e ? '; animation-timing-function: ' + e : '') + ' }';
  });
  return '@keyframes ' + name + ' {\n' + steps.join('\n') + '\n}';
}

/* 身体：水平位移、垂直位移与挤压必须在同一条 transform 里 */
out.push(keyframes(p + '-body', F, f =>
  'translateX(' + (f.dx || 0) + 'px) translateY(' + (f.body || 0) + 'px) ' + squashPair(f.squash)));

/** 挤压拉伸：横向放大时纵向压缩，面积大致守恒，看起来才有弹性 */
function squashPair(v) {
  const k = v || 0;
  return 'scale(' + (1 + k).toFixed(3) + ', ' + (1 - k).toFixed(3) + ')';
}
```

**三层外壳各管一个 transform，互不覆盖**：

```
x-stage     整体倾斜（tilt）
 └ x-fadeBox   透明度（走到边缘淡入淡出）
    └ x-spinBox  转圈（spin）
       └ x-body    位移 + 挤压
          └ ...关节...
```

### 2.5 动作从剧情推出来

页面数据里的 `pose` 是**静态姿态**（stand / lie / reach），
动画需要的是**动作**（走 / 跑 / 跳 / 摔 / 转圈 / 抱头）。中间做了一层语义推导：

```js
function actionFor(page, mid, beat) {
  const text = [(page.say && page.say.text) || '', (mid && mid.desc) || '', (page.lines || []).join('')].join('，');
  /* 台词里明确写了动作，就以它为准 */
  for (let i = 0; i < KEYWORD_ACTION.length; i++) {
    if (KEYWORD_ACTION[i][0].test(text)) return KEYWORD_ACTION[i][1];
  }
  /* 否则按故事节拍给一个贴切的表演 */
  return BEAT_ACTION[beat] || 'breathe';
}

const BEAT_ACTION = {
  curious: 'tiptoe', meet: 'reach', problem: 'back', stuck: 'cover',
  worry: 'cover', idea: 'reach', clue: 'lie', setback: 'fall',
  success: 'spin', gift: 'tiptoe'
};
```

实测 8 本分镜后的动作分布：
```
tiptoe 11   reach 13   back 10   jump 9   lie 9   spin 7   run 4   walk 3
```

### 2.6 口型同步

```js
/** 口型同步：朗读时嘴巴一张一合，停下就闭嘴 */
function mouthKeyframes(name) {
  return '@keyframes ' + name + ' { 0%,100% { transform: scaleY(1) } 25% { transform: scaleY(1.9) } ' +
    '50% { transform: scaleY(0.7) } 75% { transform: scaleY(1.6) } }';
}
/* 默认闭嘴；加上 .is-talking 才开始动嘴 */
out.push('.is-talking .' + p + '-mouth { animation: ' + p + '-talk .17s ease-in-out infinite }');
```

朗读开始加 `.is-talking`，`TTS` 的 `onEnd` 回调移除；
另加一条兜底定时器（按文本长度估算），保证嘴巴不会一直张着。

### 2.8 多实例命名（第二个必须注意的坑）

同一个页面上会同时存在多个角色的骨骼动画，
所以每个镜头的 class 都带自己的前缀（`k0-`、`k1-`…）：

```js
/* 每个角色实例一套自己的 class 名，避免同页多角色时 CSS 关键帧互相覆盖 */
const NS = prefix || 'pbA';
const g = (cls, inner) => groupCls(cls.split(' ').map(c =>
  c.indexOf('pbA-') === 0 ? NS + c.slice(3) : c).join(' '), inner);
```

否则所有实例共用 `.pbA-body`，最后一条 `@keyframes` 赢，画面会错位、头身分离。

### 2.10 视频内互动层

分镜在三个节点带 `interaction`：「第一次尝试失败」「情绪低谷」「升华与互动」。

```js
/* 视频内互动层：暂停 → 提问 → 孩子选 → 小AI 有反应 → 无缝继续 */
if (shot.interaction && S.answered[shot.index] === undefined) {
  host.appendChild(buildAnimAsk(shot, host));
}
```

- **选错**：`🤗 没关系，我们再来一次！` —— 不锁死、不变红、选项仍可点
- **选对**：`🎉 太棒了，是你帮了我！` —— 朗读这句，1.8 秒后自动进下一镜
- **连播不会跳过互动节点**：必须等孩子答完

## 三、两条路线的取舍

| 路线 | 网络 | 稳定性 | 产物 | 角色在动吗 |
| --- | --- | --- | --- | --- |
| 云端文生视频（Sora / 可灵） | 必须联网 | 排队与失败不可控，画面与绘本对不上 | 云端 URL | 是，但不可控 |
| **本机渲染 MP4** | 完全离线 | 每次结果一致 | 可下载的 MP4 | 按页停留 |
| **骨骼动画** | 完全离线 | 浏览器原生 60fps | 可互动 | **是，关节级可控** |

比赛要求「功能健全、运行稳定」，所以主推**骨骼动画**（现场演 + 互动），
**MP4** 作为「老师要带走」的补充产物。
